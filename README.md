# Security Hacks 🔐

> **名前はちょっと物騒。中身はちゃんと役立つセキュリティ手法集。**

**Security Hacks** は、セキュリティの基礎・実用的な手法・ちょっと便利な小技・よくある疑問を、**親しみやすい日本語**でまとめるリポジトリです。

「最初から教科書を全部読む」のではなく、「これって何？」「今ちょっと確認したい！」と思ったときに、**読んで、試して、理解できる**場所を目指しています。

ここでいう *Hacks* は、不正アクセスではなく、**工夫・テクニック・試行錯誤** というニュアンス。攻撃の仕組みを学ぶこともありますが、目的は理解と防御です。

## 💥 なぜ、また「教科書」を作るのか

> **セキュリティの教科書の99パーセントは無意味だ。**  
> **あんなふざけたものを読むくらいなら、同じ額を募金する方がまだ得られるものがある。**

……くらいのことは言いたい。

もちろん「99パーセント」は統計ではない。**役に立たない説明への、あえての暴言**だ。

専門用語を並べる。危機感をあおる。「意識を高めましょう」で締める。  
それで読み終わった人が **「で、結局どうすればいいの？」** と立ち尽くすなら、その教材は何のためにあるんだろう。

良い教科書や、理論そのものを否定したいわけじゃない。批判したいのは、**知っている気分だけを売って、実際には何もできるようにならない説明**だ。

そして、これはこのリポジトリ自身への挑発でもある。**Security Hacks も、読むだけで終わるなら同罪。**

だからここでは、難しいことを難しいまま放置しない。基礎は短く説明し、実例を出し、手順を示し、結果の見方と限界まで書く。

**読んだあと、何かひとつできるようになる。** それが最低条件。

## 🧰 どんな内容を集める？

- **ちいさな教科書** — 最低限の用語、考え方、仕組み
- **実用的な手順** — コマンド、設定例、調査・検証の流れ
- **小技・Tips** — 忘れやすいオプション、よくある落とし穴
- **Q&A** — 「それってどういうこと？」を短く解決
- **攻撃と防御の理解** — 何が問題で、どう防ぎ、どう確かめるか

「難しい言葉を並べる」より、**ひとつ読んだら、ひとつ役に立つ**ことを大切にします。

## ✍️ 記事の書き方：まず読者の疑問から

いきなり「〇〇とは」と始めません。まず、こんな問いを投げかけます。

> **「通信を暗号化しているから、このサイトは安全」と思っていませんか？**  
> **「ダウンロードしたファイル、途中で書き換えられていないかな？」と不安になったことはありませんか？**

そこから、**どういう問題があって、何をすればよいか**を、ふつうの言葉で説明します。

**専門用語は、意味を説明したあとで登場させる。** これが基本ルールです。

> ログインした人が、どの画面やデータを使っていいかを決めること。  
> **これを「認可」といいます。**

専門用語を覚えることはゴールではありません。でも、意味をつかんだあとで名前を知れば、もっと深く調べるときの助けになります。

記事は基本的に次の順番で書きます。

1. **こんなことありませんか？** — 読者の身近な疑問や不安から始める。
2. **何が起きている？** — まずは専門用語なしで仕組みを説明する。
3. **これを〇〇といいます** — 理解できたところで名前を紹介する。
4. **実際にやってみる** — 手順、コマンド、設定例を載せる。
5. **どう判断する？** — 結果の見方と、よくある失敗を書く。
6. **何はわからない？** — 限界を明記し、根拠となる資料を示す。

**不安をあおるだけの記事も、専門用語の暗記帳も、ここにはいりません。**

→ 詳細なルールと書き方の例は [記事の書き方ガイド](docs/writing-guide.md) を参照。

## ⚠️ 安全に試すために

このリポジトリは**学習・研究・防御・正当な検証**のためのものです。

- 検証は自分で管理している環境、または明示的に許可された範囲で行ってください。
- 他者のシステムに対して、無断で診断・攻撃・探索をしないでください。
- APIキー、パスワード、秘密鍵、個人情報などはコミットしないでください。
- 手法や設定は環境・時期によって変わります。重要な作業では公式の一次情報も確認してください。
