# 名前を入力しただけなのに、なぜ他人のデータまで見えるの？

> **「検索欄に変な文字を入れられたくらいで、データベースの中身まで変わるの？」**

## まず、検索欄の裏側を想像してみよう

ネットショップで「自分の注文」を探す場面を考えてみます。画面で入力された名前を使って、プログラムがデータベースに「この人の注文を探して」と頼みます。

データベースへの頼み方には、次の2つが混ざりがちです。

- **指示**：「名前が一致する注文を探す」
- **ただのデータ**：「名前は『あおい』」

ここで、入力された文字を**指示そのものに貼り付けたら**どうなるでしょう。入力の中に、検索条件の意味を変える文字が混ざっていると、データベースはそれを**新しい指示の一部**と受け取ってしまう場合があります。

**利用者の入力が、データベースへの命令に化ける問題。これを「SQLインジェクション」といいます。** SQL（エスキューエル）は、データベースに「探す」「保存する」などを頼むための言葉です。

## 何を間違えたの？

例えば、こんな組み立て方です。

```python
query = "SELECT id FROM orders WHERE customer = '" + user_input + "'"
```

`user_input` は利用者が入力した文字です。プログラムはこれを命令文に直接混ぜています。「文字列なのか命令なのか」を区切る記号まで混ざると、条件を勝手に変えられる可能性があります。

「特殊な文字を禁止すればいい？」と思うかもしれません。でも、名前や文章には引用符なども普通に出てきます。禁止する文字の一覧だけに頼るのは壊れやすい方法です。

## やってみよう：自分のパソコンの中だけで試す

Python 3があれば追加インストールは不要です。次を `sql_demo.py` として保存して実行してください。**外部のサーバーや本物のデータは使いません。** メモリ上に作った2件の架空の注文だけを使います。

```python
import sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE orders (id INTEGER, customer TEXT)")
db.executemany(
    "INSERT INTO orders VALUES (?, ?)",
    [(1, "aoi"), (2, "sora")],
)

# 実験用の文字列。実在するサイトでは試さないでください。
user_input = "aoi' OR '1'='1"

bad_sql = "SELECT id FROM orders WHERE customer = '" + user_input + "'"
print("混ぜてしまった場合:", db.execute(bad_sql).fetchall())

good_sql = "SELECT id FROM orders WHERE customer = ?"
print("値として渡した場合:", db.execute(good_sql, (user_input,)).fetchall())
```

```sh
python3 sql_demo.py
```

結果は次のようになります。

```text
混ぜてしまった場合: [(1,), (2,)]
値として渡した場合: []
```

最初の検索では、**2件とも見つかってしまいます**。入力が名前ではなく、検索条件の一部として扱われたからです。後半では、同じ文字列を**ひとつの名前として探すだけ**なので、該当する注文はありません。

## どう防ぐ？

**「命令の形」と「入力されたデータ」を別々に渡す**のが基本です。上の例の `?` は、値を後から安全に渡すための目印です。こうした仕組みを**パラメータ化された問い合わせ（パラメータ化クエリ）**といいます。

- **入力を文字列連結で命令に埋め込まない。** プログラミング言語やデータベースの正規のパラメータ機能を使います。
- **並べ替え順や列名は、利用者に自由に決めさせない。** `?` で置き換えられるのは通常「値」であって、列名やSQLの構造ではありません。選択肢をコード側で固定します。
- **データベース用のアカウントの権限を絞る。** 万一問題があっても、不要な操作までできないようにします。
- **データを返す前に、利用者がその注文を見る権利も確認する。** 命令文を安全に作ることと、「他人の注文を見せない」ことは別の問題です。

## ここまでは分からない

この実験は、**命令と入力を混ぜた場合の危険性**だけを示しています。「どんなデータベースでも同じ文字列で同じ結果になる」「実サービスが必ず情報漏えいする」という意味ではありません。

入力文字列を単純に置き換える、エラーを非表示にする、といった方法だけでは根本対策になりません。ORMという便利なデータベース用ライブラリを使っていても、命令文を文字連結で組み立てれば問題は起こり得ます。
