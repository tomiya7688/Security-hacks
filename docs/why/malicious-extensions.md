# 便利な拡張機能を入れただけで、なぜPCに裏口ができるの？

> **「公式っぽい名前で、いつも使っている拡張機能なら安全でしょ？ インストールしただけで、どうしてPCが危険になるの？」**

## 拡張機能は「画面の飾り」ではない

プログラミング用のエディターに、入力補助やコード検索、AIとの会話などの機能を足せるのは便利ですよね。

ところが、一部の拡張機能は**エディターを使っている人と近い権限で動くプログラム**です。VS Codeの公式資料によると、PC上で動く拡張機能は、設定や実行場所によって、例えば次のような処理ができます。

- ファイルを読んだり書いたりする
- 別のプログラムを実行する
- インターネットへ通信する
- 開いている作業フォルダーの内容を扱う

拡張機能を追加するのは、ただ「新しいボタンを画面に増やす」ことではなく、**新しいプログラムを、自分の作業環境で動かすこと**でもあるのです。

ブラウザー内だけで動く拡張機能や、別のPC・コンテナで動く拡張機能もあるため、**すべての拡張機能に同じ権限があるわけではありません**。

## 何が起こると危険？

次の2つのプログラムを考えます。

```text
もともとの拡張機能
  ① 起動する
  ② コード補助機能を表示する

悪意ある変更が混じった拡張機能
  ① 起動する
  ② 本来関係のないファイルを変更する
  ③ 外部への通信を試みる
  ④ いつもどおりコード補助機能を表示する
```

**最後の画面が同じでも、その前に何をしていたかは分かりません。**

信頼して使うソフトウェアを届ける途中の仕組みに悪いものを混ぜ、利用者に実行させる攻撃を、**サプライチェーン攻撃**といいます。

ここで「サプライチェーン」は、作ったソフトを利用者に届けるまでの流れです。例えば、作者のアカウント、公開するための設定、拡張機能の配布場所、自動更新の仕組みなど、いろいろな段階があります。

**どの段階が破られたかは事件ごとに違います。配布されたものが悪意あると確認できても、原因まで判明したとは限りません。**

## やってみよう：見た目は同じでも余計な処理が動く模型

Python 3だけで試せます。**一時フォルダーの中に無害なメモを1個作るだけ**で、SSH、実際の拡張機能、ネットワーク、システム設定には触れません。

```python
from pathlib import Path
from tempfile import TemporaryDirectory

def normal_extension():
    print("コード補助機能が使えます")

def changed_extension(workdir):
    # 利用者が頼んでいない処理を先に実行する例
    (workdir / "unexpected-action.txt").write_text(
        "起動時に別の処理も走りました",
        encoding="utf-8",
    )
    normal_extension()

with TemporaryDirectory() as folder:
    workdir = Path(folder)
    changed_extension(workdir)
    print("余計な処理の痕跡:", (workdir / "unexpected-action.txt").exists())
```

結果：

```text
コード補助機能が使えます
余計な処理の痕跡: True
```

画面に出る「コード補助機能が使えます」は本来のプログラムと同じです。しかし、起動する前に、別のファイルが作られています。

もちろん、**実際の攻撃のコードはこんなに単純ではありません**。この例は「本来の機能が正常に動くこと」と「余計な処理をしていないこと」は別、という点を示しています。

## なぜ「起動しただけ」で危ないの？

一部の拡張機能は、エディターの起動時や特定の画面を開いたときに、自動で読み込まれます。利用者が明示的に「実行」ボタンを押さなくても、**拡張機能自身のプログラムが走る**わけです。

また、拡張機能が普段使っている利用者の権限でファイルを扱えるなら、**管理者権限がないことだけでは安全といえません**。利用者自身が読み書きできるファイルに、拡張機能からもアクセスできる場合があります。

逆に、管理者権限が必要な操作は失敗することもあります。**悪意あるコードが動いたこと**と**攻撃者が遠隔操作に成功したこと**は、分けて考えましょう。

## 実際にあった例：Claude Code拡張機能の改ざん版

2026年10月、Cursorは、同社の拡張機能マーケットプレイスで、Claude Codeを名乗る悪意ある版 `anthropic.claude-code 2.1.313` が配布されたと公表しました。

調べられたコードは、本来の拡張機能が動く前に、**勝手に遠隔アクセスのための設定を追加しようとする処理**を挟んでいました。

ここで言う、**本人に知られず外部から操作するための入り口**が、**バックドア（裏口）**です。

この事故では、配布経路は**Cursorのマーケットプレイス**と説明されており、Microsoft公式Marketplaceや通常のClaudeチャットがすべて侵害されたという発表ではありません。

この事件が分かりやすく示しているのは、**拡張機能の評判や名前が本物らしくても、実際に配られたファイルの中身が安全とは限らない**という点です。

## では、どう防ぐ？

### 利用者の場合

1. **必要な拡張機能だけ入れる。** 何年も使っていないものは整理する。
2. **作者と配布元を確認する。** 名前・アイコンが似ているだけの別物を避ける。
3. **更新の出所や変更内容に注意する。** 便利な自動更新は、悪意ある更新が届く可能性もあるため、組織では配布ポリシーを決める。
4. **秘密情報の扱いを見直す。** 開発端末に不要な鍵や権限を持たせない。
5. **問題が発覚したときは、アンインストールだけで済むと思わない。** 拡張機能と別に作られたファイルや、起動時に走る設定が残る場合がある。

### ソフトウェアを配布する側の場合

- 更新版を公開できる人・仕組みを必要最小限に絞る。
- 配布用アカウントや公開手順を保護し、操作の記録を残す。
- 実際に配布した成果物が、意図したソースコードから作られたものか確認できるようにする。
- 署名や改ざん検出、ビルドの再現性、監査、検知といった**複数の仕組み**を組み合わせる。

**署名が付いている、作者が有名、バージョン番号が新しい**という理由だけで「悪意あるコードはない」と言い切ることはできません。配布時に信頼した中身そのものが悪くなっている場合があるためです。

## 「AIが言い間違えた問題」とは違うの？

**今回の型の問題は、AIの回答内容やプロンプトだけで起きるものではありません。**

AIが文章の命令にだまされる問題と、**開発ツールとして配られたプログラム自体に悪意あるコードが混じる問題**は別です。Claudeと一度も会話していなくても、拡張機能が実行されれば問題になることがあります。

## ここまでは分からない

- この実験は**拡張機能を本当に作ったものではなく**、起動時の余計な処理を表した小さな模型です。
- すべての拡張機能がOS上で自由に動くわけではありません。実行場所や機能によって制約が変わります。
- 有名な配布元でも、**絶対に安全と保証できるわけではありません**。
- 具体的な配布事故の侵入経路は、調査で明らかになるまでは推測と事実を分けましょう。
