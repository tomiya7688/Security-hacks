# 🔎 そもそも、なぜ起きる？ — セキュリティの仕組み

> **「更新しましょう」「気をつけましょう」は分かった。でも、どうしてそんな問題が起きるの？**

ここでは、セキュリティの問題が生まれる**根本の仕組み**を説明します。

ニュースや特定の製品の対策情報とは別の読み物です。「今週の事件」ではなく、数年後にも役立つ**原因の理解**を目指します。

初めて出てくる専門用語は、**まず普通の日本語で仕組みを説明してから**紹介します。「何がいけなかったか」だけでなく「どう直すか」「どこに限界があるか」も書きます。

## よくある誤解：「脆弱性の70%はメモリリーク」？

**それは正確ではありません。**

Chromiumプロジェクトは、過去に分析した重大なセキュリティ問題の約70%が**メモリを安全に扱えていない問題**だったと説明しています。分析対象は、2015年以降の高・重大度の問題912件です。これは**全ソフトウェアの全脆弱性の割合ではありません**。

そして、使い終えたメモリを返さない**メモリリーク**と、許された領域の外に書いたり、返した領域を再利用したりする**メモリの安全性の問題**は、区別が必要です。

- **メモリリーク：** メモリを返し忘れる。繰り返すと動作の遅延・停止につながることがある。
- **範囲外の読み書き：** 自分の領域でない場所を読んだり書いたりする。情報漏えいやデータの破壊につながることがある。
- **返したメモリの再利用：** もう自分のものではない領域を触る。思わぬ場所のデータを壊し、不正な動作につながることがある。

詳しい違いは2つの記事で順番に理解できます。

## この先、こんな「なぜ？」も増やしたい

- なぜ、入力がOSへの命令に化けてしまう？
- なぜ、強いパスワードでも偽サイトにだまされることがある？
- なぜ、パスワードを元に戻せない形で保存しても破られることがある？
- なぜ、正しく暗号化したつもりでも情報が漏れることがある？

**用語より、起きる理由と防ぎ方。** ひとつ読めば、同じ種類の問題を自分でも見つけやすくなる記事を増やしていきます。
