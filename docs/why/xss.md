# コメントを書いただけで、なぜ他人のブラウザーが勝手に動くの？

> **「掲示板には文字しか投稿できないはず。それなのに、なぜ危険なことが起こるの？」**

## 画面に出す「文字」と「画面を作る指示」は違う

Webページには、文字を表示するための場所があります。でも、ブラウザーは文字だけでなく、**文字の配置や動作を決める特別な書き方**も読み取ります。

例えば、次のような文字列が投稿されたとします。

```text
<b>大事なお知らせ</b>
```

これは、ただの文章として見せたい内容かもしれません。でも、Webページの一部としてそのまま組み込むと、ブラウザーは `<b>` を「太字にして」という指示として扱います。

**文章として預かった内容が、ブラウザーへの指示として解釈されてしまう。** そこに動作を指定する内容が紛れ込むと、閲覧者のブラウザーで意図しない処理が実行される可能性があります。

このような問題を**クロスサイトスクリプティング（XSS）**といいます。

## なぜ「サイトを見る人」が影響を受けるの？

投稿したのは別の人でも、表示するのはあなたのブラウザーです。

```text
誰かの投稿
    ↓
サイトが内容を保存
    ↓
あなたがページを開く
    ↓
ブラウザーが投稿内容を「表示用の文字」ではなく「指示」と解釈
```

条件によっては、サイト上で意図しない操作をさせたり、閲覧者に見える情報を外部に送ろうとしたりできます。**投稿に文字が含まれているだけで必ず攻撃になるわけではありません。** どの場所に、どう表示されるかが重要です。

## やってみよう：文字をそのまま見せる

次はPython標準機能だけの実験です。**HTML文字列を作って画面に表示するだけで、ブラウザーは起動せず、プログラムも実行しません。**

```python
from html import escape

message = "<b>大事なお知らせ</b>"

unsafe = f"<p>{message}</p>"
safe = f"<p>{escape(message)}</p>"

print("そのまま組み込む:", unsafe)
print("文字として組み込む:", safe)
```

結果：

```text
そのまま組み込む: <p><b>大事なお知らせ</b></p>
文字として組み込む: <p>&lt;b&gt;大事なお知らせ&lt;/b&gt;</p>
```

後半の `&lt;` や `&gt;` は、ブラウザーに「これは特別な指示ではなく、表示すべき記号だ」と伝える書き方です。

**特別な意味を持つ文字を、表示用の文字として扱える形に変換することを「エスケープ（出力時の符号化）」といいます。**

## どう防ぐ？

最も大事なのは、**表示する場所に合った方法で、利用者のデータを文字として扱うこと**です。

- 普通の文章をHTML本文に表示するなら、テンプレートの**自動エスケープ**を利用します。
- 画面をJavaScriptで書き換えるなら、普通の文字には `textContent` を使い、利用者の入力を安易に `innerHTML` へ渡しません。
- どうしても利用者に太字やリンクを含むHTMLを投稿させるなら、安全と判断した要素だけを残す**HTMLサニタイズ**が必要です。自作の単純な置換ではなく、保守された専用ライブラリを使います。
- 画面で実行できるコードの出所を制限する設定（**CSP**）も補助になりますが、これだけに頼りません。

**注意：HTML本文に使うエスケープを、URL・JavaScriptコード・CSSなどへそのまま流用してはいけません。** 置く場所によって、ブラウザーの解釈の仕方が違います。

## ここまでは分からない

この実験は「文字が指示に変わること」を簡単に示すものです。実際のXSSの成立条件、被害、対策は表示位置やブラウザーの機能、フレームワークの設定で変わります。

ログインCookieに `HttpOnly` を付けていても、**XSS自体が防がれるわけではありません**。Cookieを直接読めない場合でも、閲覧中のページで別の不正な動作が起こり得ます。
