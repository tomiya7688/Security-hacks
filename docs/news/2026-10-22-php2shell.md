# PHPを使ったサイト、更新を後回しにしていませんか？（PHP2Shell）

> **発表日：** 2026-10-22（IPAの注意喚起）  
> **確認日：** 2026-10-22（日本時間）  
> **対象：** PHPでWebサイト・Webサービスを運用している人  
> **公式の扱い：** IPAは「注意」として掲載

## 何が起きた？

「サイトは普通に動いているし、しばらく更新していないけど大丈夫」と思っていませんか？

2026年10月22日、IPAが、Webサイトなどの裏側で動く **PHP** に見つかった2つの問題について注意を呼びかけました。

条件によっては、サイトを管理していない第三者が、インターネット越しにサーバー上で勝手にプログラムを動かせる可能性があります。**これを「遠隔コード実行」といいます。**

この2つの問題は **PHP2Shell** と呼ばれています（CVE-2026-109618、CVE-2026-109619）。

## 自分にも関係ある？

PHPでサイトやサービスを動かしている場合は、運用中のバージョンを確認してください。IPAが案内する、修正済みのバージョンは次のとおりです。

| 使っているPHPの系列 | 修正済みのバージョン |
| --- | --- |
| 8.2系 | **8.2.35** |
| 8.3系 | **8.3.36** |
| 8.4系 | **8.4.27** |
| 8.5系 | **8.5.12** |

**それぞれの系列で、上記より前のバージョンは更新対象です。** PHP 8.1以前はサポートが終了しているため、サポート対象系列への移行も検討してください。古い系列に今回の修正が配布されるとは限りません。

自分でPHPを直接入れていなくても、CMSやホスティングサービスが内部でPHPを使っていることがあります。利用中のサービス提供元の案内も確認しましょう。

## 何が危ない？

サーバーが予想外の状態になったときの処理などに欠陥があり、特定の条件で外部からの不正な命令を実行されるおそれがあります。

「サイトが表示できる」ことと「安全に運用できている」ことは別です。一方で、**PHPを使っているサイトがすべて攻撃を受けたという意味ではありません。** 影響はバージョン、動かし方、構成などで異なります。

## 今、何をすればいい？

1. **どこでPHPを使っているか調べる。** 本番Webサーバー、コンテナ、CMS、開発・検証環境も確認します。
2. **実際にWebサイトを動かしているPHPのバージョンを確認する。** ターミナルの `php -v` は確認の手がかりになりますが、Webサーバー側が別のPHPを使っている場合があるので、**この結果だけで判定しない**でください。
3. **修正済みバージョンに更新する。** バックアップと動作確認の計画を立て、公式の手順またはサービス提供元の案内に従います。
4. **更新後に稼働中のバージョンとサイトの動作を確かめる。** インストールしただけで、古いPHPのプロセスが動いたままになっていないかにも注意します。

すぐに更新できない場合は、公開範囲の制限や一時停止も含め、管理者と対応を検討してください。**暫定的な設定変更をしただけで完全に安全になるとは言えません。** PHP開発元も修正版への更新を完全な対策として案内しています。

## どこまで分かっている？

- これは「悪用できる可能性がある欠陥」のニュースです。この記事だけで、個別のサイトが侵入されたかどうかは判断できません。
- 配布元が独自に修正を取り込む環境では、表示されるバージョン番号だけで判断できない場合があります。配布元のセキュリティ情報を確認してください。
- 新しい情報が公表される可能性があります。更新作業の直前にも公式資料を読み直してください。
