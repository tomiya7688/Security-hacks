# Claude Codeの拡張機能を更新したら、なぜPCに「裏口」ができるの？（Cursorの配布事故）

> **発表日：** 2026-10-29（米国太平洋時間、Cursorの告知）  
> **内容確認日：** 2026-10-31（日本時間。Cursorの10月30日11:30（太平洋時間）の追記を反映）  
> **対象：** 2026年10月29日の該当時間帯に、**WindowsまたはmacOS**でCursorの拡張機能マーケットプレイスから `anthropic.claude-code` **2.1.312または2.1.313** を導入・更新した可能性がある人  
> **情報の性質：** 配布経路を通じた悪意ある拡張機能の混入についての、Cursorによる事故告知

> **「Claude Codeを使っているだけで全員危険なの？」**
>
> **いいえ。** 今回確認されたのは、**Cursorの拡張機能マーケットプレイスで配布された特定の改ざん版**です。通常のClaudeチャット利用者や、すべてのVS Code拡張機能が対象という発表ではありません。

## 何が起きた？

Cursorは、2026年10月29日、同社の拡張機能マーケットプレイスで **Claude Codeの拡張機能 `anthropic.claude-code` のバージョン2.1.312と2.1.313（Windows・macOS向け）に悪意ある変更が加えられたもの**を配布したと公表しました。

同社によると、その版が配布されていたのは**10月29日午前2:27〜午後1:35頃（米国太平洋時間）**。日本時間では**10月29日18:27〜10月30日05:35頃**に当たります。

Cursorの初報を受けて報じられた「最大5,000ユーザー」は**影響を受けた可能性がある人数の上限**であり、5,000台のPCに侵入が成功したという数字ではありません。Cursorは、**悪意ある版はAnthropicが開発したものではない**としています。

攻撃者は拡張機能の起動時に動くファイルへ悪い処理を追加していました。そのため**Claudeに会話を始めさせなくても、拡張機能が読み込まれるだけで動作し得ました**。

## 何が危ない？

問題の拡張機能は、おおむね次のような動きを試みます。

1. PCのユーザー名、OS、作業場所、Gitに設定されたメールアドレス、公開IPアドレス、**秘密情報に関係しそうな環境変数の名前**などを調べる。
2. PCへ遠隔ログインするときに使えるよう、攻撃者の公開鍵を `authorized_keys` というファイルへ追加しようとする。
3. 遠隔ログインのサービスを有効にし、PCの外から接続できる経路を作ろうとする。
4. 次の起動でも同じことを試すよう、OSの自動実行の仕組みを使う。
5. 調べた情報を、攻撃者が管理するサーバーへ送ろうとする。

**所有者に知られないまま、遠くから機器を操作するための入り口を作る仕組み**を「バックドア（裏口）」といいます。

ただし、**この操作がすべてのPCで成功したわけではありません。** Cursorは、特に多くのmacOS・Windows環境では遠隔ログインサービスを有効にするための管理者権限がなく、侵入経路を開く重要な処理が失敗すると説明しています。一方、鍵や起動時の仕組みなど、**他の変更が残る可能性**はあります。

## 自分にも関係ある？

まず次の3点を確認してください。

- **どのエディターを使っていたか：** ここで確認されたのは、Cursorのマーケットプレイスを通じて入手した特定の拡張機能です。
- **どの拡張機能か：** `anthropic.claude-code`（Claude Code for VS Code）。
- **いつ・どのバージョンを入れたか：** 上記の期間に **`2.1.312` または `2.1.313`** をインストール・更新していなかったか。
- **どのOSか：** Cursorの更新された告知が影響対象とするのは **Windows・macOS** です。**Linux版の影響が確認されたとの発表ではありません**。公式にはLinuxでの痕跡の種類も紹介されていますが、対象OSの記載と混同しないでください。

現在のバージョンが新しくても、**過去に該当する2.1.312または2.1.313を起動した場合、拡張機能を更新しただけでは別途作られたファイルが残る可能性**があります。

研究者OpenSourceMalwareは、当初Open VSXでの配布としていた説明を**後から修正**し、Cursorの配布経路が問題だったと明記しています。**Microsoft公式VS Code MarketplaceやOpen VSX、通常のnpm版まで改ざんされたと断定する根拠は、確認した資料にはありません。**

## 今、何をすればいい？

### 1. Cursorでインストール履歴・拡張機能を確認する

拡張機能の画面でClaude Codeのバージョンと入手元を確認しましょう。企業のPCなら、管理者に配布履歴や端末の記録も調べてもらってください。

**「今は2.1.314だから問題なし」とは限りません。** 過去の実行履歴が重要です。

### 2. 見知らぬSSH鍵が追加されていないか確認する

攻撃コードが付ける目印の1つは `svc-telemetry` です。以下は**調べるだけで変更を加えない**コマンドです。

macOSのターミナル（**公式の確認対象OS向け**）：

```sh
if grep -q 'svc-telemetry' "$HOME/.ssh/authorized_keys" 2>/dev/null; then
  echo "疑わしいSSH鍵の目印を検出しました"
else
  echo "この検査では検出されませんでした（安全の証明ではありません）"
fi
```

WindowsのPowerShell：

```powershell
$files = @("$HOME\.ssh\authorized_keys", "C:\ProgramData\ssh\administrators_authorized_keys")
$files | Where-Object { Test-Path $_ } | ForEach-Object {
  Select-String -Path $_ -Pattern 'svc-telemetry' -SimpleMatch
}
```

**目印が見つからないだけでは感染していない証明にはなりません。** Cursorの公式告知には、調査対象のファイル・プロセス・通信先、OS別の復旧手順が掲載されています。

### 3. 該当する可能性があれば、拡張機能を消すだけで終えない

- **会社や学校の端末なら、先に管理者・セキュリティ担当へ連絡**し、調査記録を保全します。
- 悪意ある処理の実行が疑われる場合は、ネットワークから切り離すことを含めて対応します。
- Cursorの**公式復旧手順**で、悪意ある鍵、OS起動時の仕組み、動いている処理などを確認・除去します。**出所不明の修復スクリプトを安易に実行しないでください。**
- 影響を受けた可能性がある認証情報やログイン中のセッションは、**信頼できる別の端末**から無効化・再発行を検討します。
- 必要に応じてOSの再構築まで考えます。以前にPCが操作された可能性は、ファイルを消しただけで否定できません。

Cursorによれば、悪意ある版の配布は停止され、接続先サーバーも停止されたとのことです。ただし、**過去に残された変更や情報の持ち出しが自動的に元に戻るわけではありません。**

## なぜこんなことが起きた？

拡張機能は、単に文章を表示する部品ではありません。**PCでファイルを扱ったり、コマンドを動かしたりする力**を持つ場合があります。便利な機能と同じ力を、攻撃者が悪用できるのです。

利用者が信じるソフトウェアや、その配布経路を狙って悪い処理を混ぜることを**サプライチェーン攻撃**といいます。

**今回、具体的にどのような手口で改ざん版が配布経路へ入ったかは、ここで参照した資料だけでは確定できません。** 配布用アカウントが盗まれた、Anthropicが悪いコードを書いた、といった推測を事実として扱わないでください。

## どこまで分かっている？

- 確認されているのは**Cursorのマーケットプレイスで配布されたWindows・macOS向けの `2.1.312` と `2.1.313` の事故**。他の配布経路やLinux版まで一括して危険だとは言えません。
- **最大5,000ユーザー**と、**遠隔アクセスに成功したPCの台数**は同じではありません。
- 攻撃コードが最初に集める環境変数は主に**名前**です。値が一律に送信されたという発表ではありません。ただし、遠隔アクセスが成功していた場合には、それ以外の情報にアクセスされた可能性を考える必要があります。
- 遠隔ログインの有効化が失敗しても、**別の不審な変更が残ることがあります**。
- インシデントの原因や影響範囲は、その後の公式調査で更新される可能性があります。
