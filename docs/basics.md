# 5分でつかむセキュリティの基本

> 「何を守りたい？」が決まると、対策を考えやすくなる。

セキュリティは、難しい用語を暗記することではありません。**大切なものが、困った状態にならないようにすること**から始まります。

## まずは3つだけ覚えよう

| 観点 | ひとことで | たとえば |
| --- | --- | --- |
| **機密性**（Confidentiality） | 見せたくない人に見せない | 他人の個人情報を閲覧できない |
| **完全性**（Integrity） | 勝手に書き換えられない | 振込先や金額が改ざんされない |
| **可用性**（Availability） | 必要なときに使える | 障害が起きてもサービスを復旧できる |

この3つをまとめて **CIA** と呼びます（情報機関の略ではありません）。

## よく出る言葉の違い

- **資産**：守る対象。アカウント、データ、サービス、端末など。
- **脅威**：困ったことを起こす要因。不正アクセス、マルウェア、操作ミスなど。
- **脆弱性**：問題につながり得る弱点。設定ミス、未修正の不具合、過剰な権限など。
- **リスク**：何が起こり得て、起きたらどれくらい困るかという見積もり。
- **対策**：リスクを減らす工夫。権限設定、更新、バックアップ、監視など。

たとえば「公開してはいけないファイルが、誰でも読める設定になっている」は、**設定ミスという弱点**があり、**情報が漏れるリスク**がある状態です。

## 認証と認可は別物

- **認証（Authentication）**：「あなたは誰？」を確かめる。ログインなど。
- **認可（Authorization）**：「その人は何をしていい？」を決める。管理画面へのアクセス権など。

ログイン済みでも、ほかのユーザーのデータを見られてはいけません。認証が正しくても、認可が間違っていることはあります。

## 対策を考える4ステップ

1. **何を守る？** — 例：顧客情報。
2. **どう困る？** — 例：ほかのユーザーから閲覧できる。
3. **どう防ぐ？** — 例：サーバー側で、データの所有者を毎回確認する。
4. **どう気づく？** — 例：権限テストやアクセスログを用意する。

「対策した」で終わらず、**確かめる方法までセット**にするのがコツです。
