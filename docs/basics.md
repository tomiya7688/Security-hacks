# セキュリティって、まず何を守ればいいの？

> **「セキュリティ対策をしてください」と言われても、何から考えればいいんでしょう？**

そんなときは、難しい言葉を覚えるより先に、**何が起きたら困るか**を考えてみましょう。5分だけ、一緒に整理します。

## こんなことが起きたら困りませんか？

たとえば、仕事のために大切なデータを保存しているとします。

**1. 知らない人に見られてしまった**

顧客の名前や連絡先は、関係のない人に見せたくありませんよね。  
**見せてはいけない人に情報を見せないこと。これを「機密性」といいます。**

**2. 勝手に書き換えられてしまった**

請求書の金額や振込先が知らないうちに変わっていたら、大問題です。  
**情報が勝手に書き換えられず、正しい状態を保てること。これを「完全性」といいます。**

**3. 必要なときに使えなくなった**

大事な日にサービスが止まって、データを開けないのも困ります。  
**使いたいときに使えること。これを「可用性」といいます。**

この3つをまとめて、英語の頭文字から **CIA** と呼びます。まずは「見られない・変えられない・使える」を覚えておけば十分です。

## ログインできたら何でも見せていい？

こんなプログラムを書いていませんか？

「ログインしている人なら、注文情報のページを開いていい」

でも、それだけだと**ほかの人の注文情報**も開けてしまうかもしれません。

ここには別々の確認が2つあります。

- **この人は誰？** — パスワードなどを使い、誰が操作しているかを確かめること。**これを「認証」といいます。**
- **この情報を見ていい人？** — その人が、何を見たり変更したりしていいかを決めて確かめること。**これを「認可」といいます。**

ログインできたかどうかだけでなく、**その情報を使っていい人か**も、情報を返す側で確かめる必要があります。

## 「弱点がある」と「実際に困る」は同じ？

たとえば、公開するつもりのないファイルが、誰でも読める設定になっていたとします。

- 守りたいファイルやサービスなどを、**「資産」**といいます。
- 情報を盗み見られたり、消されたり、操作を間違えたりして問題が起きる要因を、**「脅威」**といいます。
- 読めてはいけないファイルが読めるような弱点を、**「脆弱性」**といいます。
- どんな問題が起こり得るか、どれくらい起こりそうか、起きたらどれくらい困るかを考えることを、**「リスクの評価」**といいます。

言葉はあとから覚えれば大丈夫。大切なのは、**何が問題で、どう困るのかを説明できること**です。

## では、何をすればいい？

身近なサービスをひとつ選んで、次の4つを考えてみてください。

1. **何を守りたい？** — 例：お客さんの注文情報。
2. **何が起きたら困る？** — 例：ほかの人が注文情報を見られる。
3. **どうやって防ぐ？** — 例：注文情報を返す前に、それを見ていい人か確認する。
4. **どうやって確かめる？** — 例：別の利用者としてアクセスしても、情報を見られないことを自分の検証環境で試す。

**「気をつけましょう」で終わらず、確認方法まで考える。** それが最初の一歩です。
