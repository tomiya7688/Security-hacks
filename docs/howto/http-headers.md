# 「HTTPSだから安全」と思っていませんか？

> **サイトの通信が暗号化されていれば、それだけで安心していいのでしょうか？**

通信が途中でのぞかれにくくなるのは大切です。でも、**サイトが画面に何を表示していいか、どんな情報をほかのサイトに渡していいか**などは、別の設定でも守ります。

ここでは、Webサイトがブラウザーに伝えている設定を、ほんの2分で見てみましょう。

**できること：** 設定の一部を実際に確認する。  
**できないこと：** この確認だけで「サイトは安全」と断定する。

## サイトは画面のほかに何を返している？

Webサイトを開くと、画面に表示する内容のほかに、サーバーから小さな「お知らせ」が送られてきます。

たとえば、

- 「次からは暗号化された通信を使ってね」
- 「読み込んでいいプログラムには制限があるよ」
- 「この情報は、決められた方法で扱ってね」

といったものです。

**Webサイトからの返事に添えられる、こうした情報を「HTTPレスポンスヘッダー」といいます。** この記事では短く「ヘッダー」と呼びます。

## まずは見てみよう

Webサイトとやり取りして、返事を表示できる小さな道具があります。**これを `curl`（カール）といいます。**

自分が管理するサイトや、閲覧を許可されているサイトで試してください。以下の `example.com` は説明用のアドレスです。

**Linux / macOS**

```sh
curl -sS -D - -o /dev/null https://example.com/
```

**Windows（PowerShell）**

```powershell
curl.exe -sS -D - -o NUL https://example.com/
```

コマンドの意味をざっくり説明すると、

- `-D -`：返事に添えられた情報を画面に出す。
- `-o /dev/null`（Windowsでは `NUL`）：画面の本文は保存しない。
- `-sS`：進み具合の表示を消す。エラーがあれば表示する。

ここでは、普段のページ表示と同じように内容を取得して確認します。`curl -I` は別の種類の問い合わせになるため、返事が違う場合があります。

## どこを見ればいい？

結果の中に、次の文字列があるか探してみましょう。出てくる項目や値は、サイトによって違います。

| 何を確認したい？ | 表示される名前 | 見方 |
| --- | --- | --- |
| リクエストは成功した？ | `HTTP/2 200` など | `200` は成功、`301` / `302` などは別の場所への案内 |
| 今後も暗号化した通信を使うようブラウザーに伝えている？ | `Strict-Transport-Security`（HSTS） | HTTPSの返事に設定されているか確認する |
| 読み込めるプログラムや画像などの出どころを制限している？ | `Content-Security-Policy`（CSP） | 項目があるかだけでなく、どんな制限かを見る |
| ファイルの種類をブラウザーが勝手に推測しないようにしている？ | `X-Content-Type-Options: nosniff` | `nosniff` が設定されているか見る |
| ログイン状態などの小さな情報を保存させている？ | `Set-Cookie` | `Secure` や `HttpOnly` などの指定を見る |

※ 最後の情報は、ブラウザーに保存され、次のアクセス時にも使われることがあります。これを **Cookie（クッキー）** といいます。

**重要：項目が見つからなくても、即座に「危険」と決めつけないでください。** サイトの仕組みや目的によって必要な設定が変わります。項目があっても設定内容が不適切な場合があります。

## 別の場所に案内されたら？

「このURLではなく、こちらに来てください」という返事があります。これを **リダイレクト** といいます。

案内先まで見たいときは、`-L` を追加します。

**Linux / macOS**

```sh
curl -sS -L -D - -o /dev/null https://example.com/
```

Windowsでは `/dev/null` を `NUL` に置き換えてください。途中で返された情報もまとめて表示される場合があるので、どの返事の内容かに注意しましょう。

## うまくいかなかったら

- **`301` や `302` だけ出た**：`Location` という行を確認する。必要なら `-L` を使う。
- **`curl` を実行できない**：インストール状況を確認する。Windowsなら `curl.exe` を使う。
- **探した項目が見当たらない**：必ずしも設定ミスではない。サイトの役割を確認する。
- **Cookieが見えない**：ログイン時だけ発行されるなど、ページや状況によって違うことがある。

## まとめ

**これでわかること：** Webサイトが返した設定の一部。

**これだけではわからないこと：** サイト全体の安全性や、実際に攻撃を防げるかどうか。
